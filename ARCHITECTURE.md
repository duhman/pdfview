# PDFView architecture

PDFView is a native macOS PDF reader with offline visual signing, built with Swift 6, SwiftUI, AppKit, and PDFKit. It targets macOS 14.2 and later.

This document describes the current source. Interactive behavior still requires the on-screen checks listed below.

## Document model and export

`PDFViewerDocument` owns the document's live PDFKit document and signature placements in PDF page coordinates. Export captures the live, unlocked document so edits to forms survive; the async path captures immutable `CGPDFPage` content, recursively frozen annotation properties, page geometry, navigation and form values in one main-actor step before its first suspension. It builds the expensive private annotation objects on the worker instead of copying the whole PDFKit document on main. The returned `ExportedState` contains the exact placements and form values written; save-before-close/quit compares both against live values and leaves changed windows edited. `writableContentTypes` is explicitly empty so the viewer does not advertise an unsigned Save As writer. Later form, annotation and page edits cannot mix states across exported pages. The viewing document lifecycle keeps opening and reading separate from the explicit Save Signed Copy action.

`SignedPDFExporter` renders page content and visual signature stamps into a flattened copy. It preserves media/crop boxes and rotation, restores link annotations and the outline by page index, and copies document attributes. Signature images fit within their placement bounds without changing aspect ratio. Export stages output on the destination volume, validates the result, then replaces the destination atomically. An image-rendering or write failure must not silently produce an incomplete copy.

Flattened stamps are page artwork. This is not certificate signing, identity verification, or tamper protection.

## PDFKit bridge and interaction

`PDFKitView` bridges PDFKit into SwiftUI. A `PDFPageOverlayViewProvider` draws signature overlays that follow each page during scrolling and zooming. Placement, selection, moving, and aspect-locked resizing use page coordinates; the document model remains the source of truth. Undo and redo operate on model changes, registered with the window's undo manager (the document has none, so macOS never treats it as edited). `UndoCommands` replaces SwiftUI's Edit > Undo and Redo: `UndoMenuModel` follows the key window's undo manager through undo-manager and key-window notifications so the titles carry the action name, and the items send the standard `undo:`/`redo:` actions through the responder chain.

Signing mode consumes placement clicks while normal reading retains PDFKit's selection and navigation behavior. Only signature widgets are treated as signature fields. `FormScan` uses `ReaderController.scanSignatureFields` to collect named signature fields and editable widgets in one cancellable page walk after the pages are shown; it reruns when a protected document is unlocked. Overlays redraw only when their inputs (placements, mode, stamp image, fields, selection) change.

Each page overlay exposes its stamps as `StampAccessibilityElement` buttons labelled by `StampAccessibility` (signer, page, field or on-screen position, with PDF-supplied field names flattened and truncated) and offering Remove and Move actions named for the stamp's kind. Keyboard editing lives in `PDFKitView+Keyboard`: `PlacementGeometry.arrowAction` maps arrows to a 1 pt move, Shift-arrows to 10 pt, Command-arrows to 50 pt and Option-Shift arrows to a resize, and never claims Option, Option-Command or Control arrows. The PDF view claims those chords before the menus only while a stamp owns the arrow keys: the coordinator's `stampOwnsArrowKeys` is set by a click, Select Next Stamp or VoiceOver's Move action, and stays off for a stamp that was just placed, so reading with the arrows keeps scrolling. `SigningFlowLogic.stampToSelect` makes Select Next Stamp take that just-placed stamp first. Escape follows `SigningFlowLogic.escapeAction` (export, signing, Find, selection, then the saved banner) and announces a deselect; the Find field closes Find itself. Actions that do nothing report why through `TransientNotice`, a four-second message in the signing banner (or a notice banner when not signing) that VoiceOver also hears; a cancelled save or print, and a cancelled save panel, report "Save cancelled." the same way (`ExportPurpose.feedback`, `ExportPurpose.savePanelNotice`). Commands whose shortcut would otherwise beep stay enabled while a document is open and explain instead: Place Signature in Next Field (`SigningFlowLogic.signingUnavailableReason`, `nextFieldUnavailableReason`), Select Next/Previous Stamp (`noStampsNotice`) and Next/Previous Form Field (`FormFieldNavigation.unavailableNotice`). After a placement the banner shows `StampAccessibility.placedNotice` for eight seconds, built from the same sentences as the VoiceOver `placedAnnouncement`, so both say how to select the stamp for the arrow keys and, for the first initials on a multi-page PDF (`SigningFlowLogic.offersInitialsOnEveryPage`), how to initial the other pages. Sign > Anywhere is enabled only while signing (`SigningFlowLogic.anywhereIsEnabled`). The saved banner names the folder with `SigningFlowLogic.folderDisplayName`, which abbreviates against the account's home folder from the user database because `NSHomeDirectory()` is the sandbox container. `DelayedVisibility` holds the progress banner back for 300 ms so quick exports never flash it. Overlay outlines take their widths and darkening from `OverlayStyle`, which follows Increase Contrast and redraws when it changes.

`PlacementChoices` gives each stamp kind its own Fields/Anywhere entry mode for the window: Signature defaults to Fields when the PDF has signature fields, Initials and Date to Anywhere. `SetupRequest` records the kind and mode before a setup sheet opened on the way to a stamp, and Cancel restores them. `StampWorkflow` holds the stamp rules the views share: the active kind returns to Signature after each placement or exit, menu titles name the active kind, Place in Next Field picks the next field with no stamp centred in it, and Place Initials on Every Page computes one rect per page without initials (the selected or last initials' position relative to each page, or the on-screen bottom-right margin) and adds them through `SignaturePlacementEditor` as one undo group. `StampSizeMemory` gives each kind a default width (signature 180, initials 60, date 110 pt) and remembers the last resize per kind for the app session. `MenuShortcuts` lists every menu chord so a test can check them for duplicates and standard-chord collisions; its `entries` table (checked to cover every chord once) generates Help > Keyboard Shortcuts, and `display`/`spoken` format chords for that window, the signing banner and VoiceOver.

Go > Next/Previous Form Field (`FormFieldNavigation`) walks the scanned non-signature widgets in reading order, skipping read-only ones, reveals each and announces its name, kind and page. Landing on a widget other than a text field makes the PDF view first responder, which ends any PDFKit text edit so Space and Return reach the activation handler. PDFKit has no public API to begin editing a widget, so an editable text field gets a click at its centre, and only when `SigningPDFView.widgetClickPoint` confirms the widget is the topmost annotation there, the point is visible and the PDF view itself is under it. Other widget kinds are never clicked. Go > Activate Form Field (or Space/Return on the field just moved to, until another key, click or scroll) acts on that widget through `PDFKitView+Forms`: checkboxes toggle, radio buttons turn on and their group off, pop-up and list fields offer their choices in a native menu, text fields are clicked as above, and push buttons are left alone because they can run the PDF's actions. Each change is announced with its new state (`FormFieldNavigation.spokenState`) and reported as a form edit.

`PDFContentView` coordinates the toolbar, sidebar, signing setup, and document status. `SigningCommands` routes app menu commands to the focused document. Unsaved work is placements not in the last saved copy plus form values that differ from the last saved copy; removing every saved stamp or reverting a saved form still allows saving the current state. Until the first export, form comparisons use `DocumentProtection`’s baseline captured synchronously at load or successful unlock, including before the reader scan reports values; the close guard reads it at decision time, and `AppDelegate` runs `TerminationReview` over guards found in `NSApplication.windows`, including hidden and minimized document windows, when the app quits. Saving reports success only after export finishes.

## Signature creation and storage

One app-wide `SignatureStore` is injected into document windows. It persists a signature and optional initials profile locally in the sandbox's Application Support directory and validates that stored image data decodes. `profile(for:)`, `saveProfile(_:for:)`, and `deleteProfile(for:)` operate on either `SignatureKind`; the existing `profile` property and default save/delete arguments still address the signature. Loading accepts the original bare-profile JSON; the next successful mutation writes both profiles atomically in one envelope. It does not upload or sync signatures.

`SignatureRenderer` handles drawn, typed, and imported artwork. Drawing uses a paper-white surface with black ink, smooth strokes, single-tap dots, uniform scaling, and crop-to-ink bounds. Typed signatures fit their names; imported images can remove white backgrounds. Editing restores existing artwork instead of discarding it.

`SignatureSetupSheet(existingProfile:kind:fullName:onCancel:onSave:)` supports both kinds, defaulting new initials to the first character of each name component. Its native drawing canvas becomes first responder and registers strokes and clearing with the sheet window's UndoManager; undo restores saved artwork when appropriate. Text fields retain native text undo. `SignatureRenderer.renderDate` returns transparent artwork with today's date, the current locale and time zone, and medium date style, set in the system font at medium weight (`dateFont`). Date, locale and time zone are injectable. The text fit repeats until it fits, because the optically sized system font widens as it shrinks.

The Sign menu and compact toolbar menu select Signature, Initials, or Date. Missing initials open setup with kind `.initials` and resume the pending action after saving. `StampArtwork` snapshots the selected profile or uses date artwork cached by local calendar day, locale and time zone; each placement records kind, image bytes, signer and optional formatted date. All kinds share field/free placement, selection, move/resize, undo and export. VoiceOver labels name the stamp kind and signer or date.

## Reader features

The reader provides a page indicator, Go to Page, thumbnails and outline sidebar, Find, Print, remembered position, single/two-page layouts, and full screen. Zoom tracks fit and manual modes separately so view updates do not reset the user's zoom. Printing includes the visible signature placements through the export path.

`ReaderController` observes PDFKit page/scale and clip-view scroll changes, owns per-window sidebar/layout state and restores reading destinations after the view attaches or the PDF unlocks. `ReaderSidebar` binds a `PDFThumbnailView` to that same PDF view and renders a recursive outline. `ReaderCommands` uses the existing focused-scene action pattern for View, Go, Find and Print; standard SwiftUI window commands retain native full screen. Plain arrow and Page Up/Down events remain with PDFKit, except when a selected signature owns arrow-key editing.

`FindController` cancels prior searches and observes `PDFDocumentDidFindMatch` / `PDFDocumentDidEndFind` on the main queue. Generation checks discard queued stale callbacks; PDFKit selections remain on the main actor. `FindState` holds tested match counting and wrapping. The find bar requests text focus when opened; Escape in the Find field closes Find, and elsewhere finishes signing before closing Find. During export, Escape cancels the export first.

`ReadingPositionStore` is a Codable value with SHA-256 keys derived from standardized file paths. UserDefaults retains at most 200 entries in least-recently-used order. Values contain the page index, destination point and fit/manual zoom; paths and security bookmarks are not persisted. Invalid, corrupt or out-of-range positions are ignored.

`SignedCopyOperation` reserves the window's save slot before opening a save panel and prevents duplicate saves/printing while busy. It rejects the original by resolved path or file/volume resource identity, including symlinks and hard links. The exporter rechecks identity before committing. After main-actor snapshot capture, a detached worker exclusively owns the private geometry/navigation document, retained immutable `CGPDFPage` content and frozen annotation properties. It constructs annotation objects and draws them over the original page content on that worker. Its private ownership-transfer box is `@unchecked Sendable` because PDFKit does not declare Sendable; no live reader document or pages enter it. Rendering, synchronous serialization, geometry repair, validation and atomic replacement run off the main actor; only progress callbacks hop to main. Cancellation propagates to the worker and is checked between pages and finalization stages, and immediately before replacement. Placements are captured at the start; later placement edits remain unexported. `PDFPrinting` checks source print permissions, prepares a temporary signed PDF when needed, retains it through the native print operation with auto-rotation, and removes it after completion, cancellation or error.

`DocumentProtection` owns an in-memory password for one open document and calls PDFKit's unlock API. `UnlockDocumentSheet` provides secure entry, wrong-password feedback and Cancel, announces its title and instruction when it opens, and the window announces "Unlocked, N pages" once it closes after a correct password. The save accessory defaults to keeping protection when the password is known, exposes an explicit opt-out, and explains that an unknown password means an unprotected copy. Export captures access permissions and the opening credential's user/owner role before freezing the live document. It passes PDFKit's `accessPermissionsOption` with the password options. For user-unlocked sources it generates a separate private owner password, so the retained user password cannot grant owner privileges; the unknown original owner password is not retained. Owner-unlocked sources keep the known password as an owner credential. Before replacement, export unlocks the protected output with the opening password and requires the full permission mask and credential role to match. PDFKit cannot round-trip every permission combination; a mismatch fails with an explanation and leaves the destination unchanged. Encrypted output needing nonzero-origin geometry repair fails safely: appending plaintext streams would corrupt the encrypted file. The error offers turning off Keep password protection, and suggests normalization through Print only when the source permits printing.

### Window integration

`DocumentProtectionSession` retains one `DocumentProtection` for the current PDF identity and discards it on replacement. A locked PDF opens `UnlockDocumentSheet`; Cancel leaves a banner naming unavailable actions and offering Unlock. File > Unlock… retries while locked. `PDFContentView.documentForPageView` withholds a locked document from PDFKit, so its native password field never appears and the sheet is the only unlock surface; a placeholder covers the empty view. Unlocking hands PDFKit the document, which restarts the field scan, and `PDFViewerProxy` moves keyboard focus into the document once it is shown (also when a window first opens).

After reserving its export slot, `PDFContentView` calls `SignedCopyOperation.configure(_:originalURL:protection:)` before presenting the save panel. This supplies SwiftUI’s original URL even when PDFKit parsed bytes and has no `documentURL`, installs the protection accessory, and passes its choice into writing. Printing uses the same selected password for a temporary signed export, unlocks it in memory for AppKit, and removes the temporary file on completion, cancellation or failure.

`FormScan` collects widget references through the G1 scanner’s per-page callback instead of owning a second signature-field traversal. The coordinator cancels scans on unlock, replacement and dismantle, checks cancellation and document identity before publishing results, and keeps the editable form baseline scoped to that PDF. `PDFViewerDocument` captures all editable widget references and initial values synchronously on load. `DocumentProtection` reuses that baseline, or captures it synchronously on unlock (including PDFKit native unlock notifications). Close decisions read these live widget references even while signature discovery is suspended; locked documents have no unsaved work, while unavailable values on an unlocked document conservatively count as unsaved work.

`ReaderController` scopes bounds notifications to the PDF view's clip view. It indexes outline destinations by page at refresh and caches the current section, including missing entries, per visited page. Section lookup never requests a page text selection and works for image-only pages.


## Privacy and file access

The app is sandboxed with user-selected read/write file access, printing permission and no network entitlement. User-selected import/export URLs use security-scoped access where needed. Signature profiles remain on this Mac. PDF data and signature images still require validation at their input boundaries; using Swift does not eliminate risks in document parsing.

## Packaging and distribution

`build_app.sh` builds with SwiftPM using stock macOS Bash 3.2, locates the executable through SwiftPM, and packages `PDFView.app`. It copies the Info.plist template, app icon, and sandbox entitlements, patches version metadata, and signs the executable and bundle. `ARCHES="arm64 x86_64"` produces a universal executable before signing.

`scripts/make-icon.swift` draws the icon procedurally with Core Graphics, exports the standard iconset resolutions, and invokes `iconutil`. The committed `Resources/AppIcon.icns` is the packaging input; regeneration requires only Swift and the macOS SDK.

Ad-hoc signing is the default. Optional Developer ID notarization submits a `ditto` ZIP, checks for Accepted, staples and validates the app, and rebuilds the ZIP with the ticket. Releases are built locally and currently distribute an ad-hoc signed app; the README documents the Gatekeeper override for each macOS version.

## Verification

Swift Testing covers document/export behavior, signature rendering/storage, reader logic, asynchronous find, position restoration, signed print preparation, export progress/cancellation and an isolated-process, 300-page image-heavy main-actor heartbeat regression bounded to 250 ms through rendering and all finalization stages. Geometry, navigation, attribute and atomic-write tests use the same async exporter as production; there is no separate synchronous writer. An isolated-process 300-page, 2,000-widget fixture measures synchronous form capture at open (250 ms bound; 47-103 ms measured, mostly PDFKit's lazy annotation parse) and through the entire save capture to first suspension (100 ms bound), plus a 250 ms heartbeat bound through the widget export. The image-heavy regression also bounds the initial capture to 100 ms; capture remains synchronous to keep the baseline-before-edit and snapshot-plus-values guarantees. Bundle checks cover Bash compatibility, resources, architectures, metadata, and signature integrity. `scripts/ci-local.sh` runs every check locally (there is no hosted CI); lint never rewrites the checkout.

On-screen verification remains necessary for menu routing, scrolling/zoom overlays, accessibility, multiwindow behavior, and first-launch Gatekeeper dialogs. Local builds and rendered bitmap checks do not establish that these UI flows or Apple's live notarization service succeeded.
